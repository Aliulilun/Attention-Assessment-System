# 打包說明（給開發者）

把整個專案打包成免安裝發佈版，讓別人下載解壓縮後直接雙擊就能跑分析。
採用 **conda-pack**：把你本機的 `mediapipe_py39` 環境整包壓縮，
對方不需要安裝 Anaconda，也不需要 `pip install` 任何東西。

---

## 怎麼跑

```powershell
conda deactivate
C:\project\packaging\build_release.bat
```

雙擊 `build_release.bat` 也可以。**預留 15～40 分鐘**，最慢的一段是
`conda pack`（把 5～6 GB 的環境壓成 tar.gz）。

執行過程中至少需要 **20 GB 可用硬碟空間**。

---

## 它會做什麼

| 步驟 | 內容 |
|---|---|
| 1 | 建立乾淨的 `C:\project\release\`（**會先刪掉舊的**） |
| 2 | 用 robocopy 複製程式碼與模型到 `release\app\` |
| 3 | 收集 Whisper / EasyOCR / Ultralytics 的模型快取到 `release\assets\` |
| 4 | 在 base 環境安裝 `conda-pack` |
| 5 | `conda pack -n mediapipe_py39` → `release\env.tar.gz` |
| 6 | 複製 `START_UI.bat` 與 `README_FIRST.txt` |

### 產出結構

```
release\
├── START_UI.bat        對方雙擊這支
├── README_FIRST.txt    對方的使用說明
├── env.tar.gz          打包好的 Python 環境（4~6 GB）
├── assets\
│   ├── whisper\        large-v3.pt（約 2.9 GB）
│   ├── EasyOCR\        偵測與辨識模型（約 100 MB）
│   └── Ultralytics\    設定與字型
└── app\
    ├── ui\ modules\ hurry\ model\ summarize\ docs\
    ├── main.py  config.yaml  ffmpeg.exe  README.md  CLAUDE.md
    ├── hurry\video\    空的（對方放測試影片）
    └── hurry\output\   空的（分析結果會出現在這）
```

總計約 **7～9 GB**。壓縮後 5～7 GB。

---

## 排除了什麼

robocopy 的 `/XD` 會排除**任何深度**下叫這些名字的資料夾：

- `video`、`output` — 同時涵蓋 `hurry\video`、`hurry\output`。
  **所有受試者影片與既有分析結果都不會被打包。**
- `release`、`packaging`、`.git`、`.vscode`、`__pycache__`、`.venv`

另外用完整路徑排除 `summarize\files`、`summarize\output`——那裡有約 70 份
分析報告，`.txt` 內含完整逐字稿與原始影片路徑。`summarize\summarize.py`
程式碼仍然會打包，只是不帶資料。

再用 `/XF` 排除 `*.pyc`、`groups.json`（本機 ASD/TD 分組）、
`speech_cache.json`（含逐字稿的語音快取）。

---

## 打包完的檢查清單

跑完之後、壓縮之前，請確認：

- [ ] `release\env.tar.gz` 存在，而且有好幾 GB。**如果只有幾 KB，代表 `conda pack` 失敗了**
- [ ] `release\assets\whisper\large-v3.pt` 存在（約 2.9 GB）
- [ ] `release\app\hurry\video\` 裡**只有** `PUT_VIDEOS_HERE.txt`
- [ ] `release\app\hurry\output\` 裡**只有** `RESULTS_APPEAR_HERE.txt`
- [ ] `release\app\video\`、`release\app\output\` 是空的
- [ ] `release\app\summarize\files\` 裡**只有** `PUT_REPORTS_HERE.txt`

前兩項是最重要的：`env.tar.gz` 太小代表 `conda pack` 失敗，
Whisper 權重缺席則對方首次分析要另外下載 2.9 GB。

---

## 對方那邊會發生什麼

雙擊 `START_UI.bat`：

1. **首次**：用 Windows 內建的 `tar` 解開 `env.tar.gz` → `env\`（5～15 分鐘）
2. **首次**：執行 `conda-unpack` 修正環境內寫死的絕對路徑，
   完成後留下 `env\.unpacked_ok` 標記檔
3. **首次**：把 `assets\` 的模型快取複製到對方的家目錄
   （`~\.cache\whisper`、`~\.EasyOCR`、`%APPDATA%\Ultralytics`），
   用 robocopy 的 `/XC /XN /XO` 保留對方已有的檔案不覆蓋
4. 執行 `env\Scripts\activate.bat`（讓 `Library\bin` 進 PATH，CUDA 與 Qt DLL 在那裡）
5. `start "" env\pythonw.exe ui\app.py` — 用 `pythonw` 才不會留下黑視窗

第 2 步之後每次啟動都會跳過 1～3，只花 10～20 秒。

## 已知限制

**對方仍然需要 NVIDIA 顯卡**
CUDA runtime 在 torch 套件裡會一起打包，但**顯示卡驅動程式**是作業系統層級的，
必須是對方電腦上已經有的。沒有的話介面能開、報表能看，但分析會慢到不能用。

**路徑不能含中文或空白**
conda-pack 產生的環境對路徑比較敏感，`README_FIRST.txt` 已經提醒對方
解壓縮到 `D:\attention` 這類純英文路徑。

**Windows 版本**
`tar.exe` 從 Windows 10 build 17063（2017 年底）開始內建。更舊的版本
需要對方自己用 7-Zip 解開 `env.tar.gz`，`START_UI.bat` 偵測到這種情況
會給出明確指示。

**這個腳本我沒辦法替你驗證**
它必須在有 conda 環境的機器上跑，我這邊沒有你的環境。
第一次執行時請留意每一步的訊息，任何一步失敗腳本都會停下來並顯示原因。

# 第二種發佈：跨平台結果檢視器

給 **Mac 使用者、或沒有 NVIDIA 顯卡的人**。只能閱讀分析報告，
不含 AI 分析功能，因此不需要 GPU、不需要下載模型。

```powershell
C:\project\packaging\build_viewer_release.bat
```

幾秒鐘跑完，產出 `C:\project\release_viewer\`，**只有幾百 KB**。

```
release_viewer\
├── START_VIEWER.command   macOS / Linux 啟動器
├── START_VIEWER.bat       Windows 啟動器
├── 使用說明.txt            接收方的中文說明
├── reports\               放要看的 .txt 報告（預設空的）
└── app\
    ├── ui\                介面程式碼（含 viewer.py）
    └── modules\           stage_scoring 等純 Python 模組
```

## 為什麼這個版本可以跨平台

完整版必須綁 Windows + NVIDIA，原因是打包的 conda 環境裡是 Windows
執行檔（`.dll` / `.pyd`），而且 PyTorch 用的是 CUDA build——macOS 沒有
CUDA，Apple Silicon 用的是 MPS。

檢視器只用到 `ui/report_parser.py`、`ui/widgets.py`（QPainter 自繪圖表）
與兩個頁面，相依套件只有 PySide6 與 pandas，兩者在 macOS arm64 都有官方
wheel。啟動器會在資料夾內建一個 `.venv` 自行安裝，不污染系統 Python
（macOS 內建的 Python 受系統保護，直接 pip install 會被擋）。

`ui/pipeline_api.py` 雖然被兩個頁面 import，但它對 `hurry/main.py` 是
**延遲載入**的（`get_hurry_main()` 被呼叫時才 import），檢視器不會走到
那條路徑，所以不會拉進 torch。已實測驗證：檢視器啟動後
`sys.modules` 裡沒有 `torch`、`ultralytics`、`hurry_main`。

## macOS 的兩個坑

**1. 執行權限會在壓縮時遺失**
Windows 的 ZIP 不保存 Unix 權限位元，`START_VIEWER.command` 到了 Mac
會沒有執行權限。`使用說明.txt` 因此把「在終端機輸入 `bash ` 再把檔案
拖進去」列為第一推薦做法——這個方式不需要執行權限，一定能動。

**2. Gatekeeper**
從網路下載的腳本，直接雙擊會被擋。說明裡有寫要用
Control + 點選 →「打開」。

## 給誰用哪一份

| 對方的機器 | 給哪一份 | 能做什麼 |
|---|---|---|
| Windows + NVIDIA 顯卡 | `release`（7.2 GB） | 完整分析 + 看報表 |
| Mac（Apple Silicon / Intel） | `release_viewer`（幾百 KB） | 只能看報表 |
| Windows 無獨立顯卡 | `release_viewer` | 只能看報表 |

要讓 Mac 也能跑分析，得在 Mac 上重建環境、把 `config.yaml` 的
`device` 從 `cuda` 改成 `mps` 或 `cpu`，並確認 ultralytics / EasyOCR /
Whisper 在 MPS 上的行為。工作量不小，而且沒有 CUDA 的話速度差很多，
目前不建議。

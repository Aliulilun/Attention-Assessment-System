### N3【中】✅ 已修（2026-09-17）`GazeHoldTracker` 的雙側打斷是不對稱的

**104-S7 的具體問題在 `interaction.py:240`**：

```python
cx, cy = sum(xs) / len(xs), sum(ys) / len(ys)      # 只用臉部關鍵點平均
spread = max(max(xs) - min(xs), max(ys) - min(ys)) / 2.0
scale_based = float(person.get("scale", 0.0)) * self.HEAD_SIZE_FROM_SHOULDER
r = max(spread, scale_based, 1.0)                   # 半徑有肩寬當地板值
```

半徑已經有「肩寬推估」當地板值（`HEAD_SIZE_FROM_SHOULDER`），**但中心點沒有對應的保護**——側臉只剩鼻子一個關鍵點時，`cx, cy` 就是鼻尖座標，而鼻尖在側臉時位於頭部輪廓的邊緣、不是中心。建議做法與半徑對稱：關鍵點數量少於 N 個時，改用肩膀中點 + 垂直偏移推算中心，而不是只用僅存的一兩個臉部點。

## 五、驗收標準（沿用指向報告第八節，補上本份的新增項）

每次改動固定回報：

```
Pointing 精確率 = TP/(TP+FP)     現況 21.8%（全量舊快照）    目標 > 60%
Pointing 召回率 = TP/(TP+FN)     現況 47.2%                  守住不低於 45%
ASD/TD 誤報率比值                現況 15.4%/6.4% = 2.4       目標接近 1.0
Stage 8 AI 指向人數              現況 20，人工 2
TH 精確率 / 召回率               現況 78.3% / 91.2%
TB 精確率 / 召回率               現況 95.9% / 96.9%   ← 這條是煞車，不該變差
```

**新增兩條驗收規則**：

1. **人工真陽性清單必須由腳本產生**，不得手工維護（N1 的教訓）
2. **指向改動不得只用現行 10 支 benchmark 驗收**（N2 的教訓）——那組樣本只涵蓋 12.8% 的指向真陽性

## 六、V1 方法論備忘的延伸（新增 2 條）

接續 V1 的 10 條，本次核對再補兩條：

11. **「已知的真陽性清單」本身也需要驗證。** V1 的紅線清單經過一次修正（2 格 → 3 格）之後就被當成定論，實際上仍漏了 2 格。凡是手工維護、被拿來當驗收依據的清單，都要定期用程式重算一次。

12. **驗收樣本的代表性要跟著驗收目標走。** 現行 10 支 benchmark 是為了診斷 TH 挑出來的，對 TH 涵蓋 15.7%、對指向只涵蓋 12.8%。用同一組樣本驗收不同構念，等於在雜訊裡找訊號。

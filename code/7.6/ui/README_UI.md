# 圖形化介面操作說明

供「軟硬體專題」報告展示使用。介面本身**不做任何分析判斷**，所有 T0 / TB / TH
計分仍由 `hurry/main.py` 與 `modules/` 負責，因此介面顯示的數字與命令列版本完全一致。

---

## 1. 安裝（只需做一次，本機已完成）

```powershell
conda activate mediapipe_py39
pip install PyQt5
```

> **這台機器要用 PyQt5，不要用 PySide6。**
> `mediapipe_py39` 的 `Library\bin` 裡已經有另一套 Qt6 DLL，會被優先載入，
> 導致 PySide6 匯入時噴 `DLL load failed while importing QtCore: 找不到指定的程序`
> （載到的 Qt6Core.dll 缺少 PySide6 需要的函式）。重裝 PySide6 解決不了。
> PyQt5 用的是 Qt**5**，DLL 檔名不同（`Qt5Core.dll` vs `Qt6Core.dll`），不會衝突。
>
> 介面透過 `ui/qt_compat.py` 自動偵測可用的綁定，兩者皆可，程式碼不需修改。
> 換到別台機器若 PySide6 沒問題，直接裝 PySide6 也能跑。

## 2. 啟動

雙擊 `C:\project\run_ui.bat`，或：

```powershell
conda activate mediapipe_py39
cd C:\project
python ui\app.py
```

首次開啟需載入 PyTorch，約 10–20 秒。

## 3. 報告當天的建議流程

| 步驟 | 頁面 | 動作 | 講什麼 |
|------|------|------|--------|
| 1 | 影片載入與設定 | 選一支**已跑過**的影片，展示右側參數 | 說明跳幀、關卡範圍、視線校正這些參數各自控制什麼 |
| 2 | 即時監測 | 選一支**短影片**按「開始分析」 | 影片上的黃框亮起 ⇄ 右側 Gazing 燈亮 ⇄ 表格 TB 次數 +1，讓觀眾自己把三者串起來 |
| 3 | 單次結果報表 | 分析結束會自動跳轉 | 各關得分長條圖、反應等級圓環、逐字稿裡的關鍵字就是 T0 依據 |
| 4 | 歷史統計比較 | 在表格「分組」欄標 ASD / TD | 各關平均得分的組間差異，並示範匯出 Excel |

### 一次跑多支影片（批次分析）

影片清單每一列前面都有勾選框：

1. 勾選要跑的影片，或用下方的 **全選** / **只選未分析** 快速挑
2. 按鈕會變成「開始批次分析（N 支）」
3. 系統依序跑完，監測頁標題顯示「第 N / M 支」

批次時的幾個行為：

- **模型只載入一次**：第二支之後直接沿用，省掉每支 30 秒以上的冷啟動
- **主控台不清空**：第二支之後保留前面的訊息，方便回頭追
- **單支失敗不中斷整批**：跑一整晚時，不該因為第 3 支壞掉就全停。
  失敗的影片會記下來，結束時彙總顯示
- **「停止分析」= 中止整批**：目前這支仍會寫出報告，後面沒跑的直接跳過
- **一個都沒勾**：就分析目前反白的那一支（單支分析是最常見的操作，
  不該強迫先去勾一個框）

### 現場保險做法

- **先跑過一次**：Whisper 語音辨識第一次要跑數十秒到數分鐘，跑過之後會存快取，
  現場再按「開始分析」就會直接跳過語音階段，只剩逐幀分析。
- **挑短影片**：現場示範建議用 1–2 分鐘的片段，跑完整支 6 分鐘影片會等太久。
- **想加速**：把「OCR 跳幀」調到 10、「YOLO 跳幀」調到 2。這會犧牲一些判定精度，
  只適合展示流暢度，正式數據仍請用預設值（OCR=5、YOLO=1、視線=1）跑。
- **中途要停**：按「停止分析」，已分析的部分仍會寫出報告與影片，不會白跑。
- **萬一當場出錯**：直接切到「單次結果報表」按「開啟報告檔…」載入
  `hurry/output/` 裡先前跑好的 txt，四個頁面的展示流程照樣走得完。

## 4. 檔案結構

```
ui/
├── app.py             主視窗、側邊導覽、四個頁面的串接
├── qt_compat.py       PySide6 / PyQt5 相容層（唯一碰到綁定差異的地方）
├── theme.py           深色主題 QSS 與色票
├── pipeline_api.py    以 importlib 把 hurry/main.py 當函式庫載入
├── workers.py         QThread：語音辨識 → 載入模型 → 逐幀分析
├── widgets.py         共用元件與自繪圖表（長條、分組長條、圓環、時間軸）
├── report_parser.py   event_record txt → 結構化資料
└── pages/
    ├── setup_page.py     ① 影片載入與參數設定
    ├── monitor_page.py   ② 即時監測主畫面
    ├── report_page.py    ③ 單次結果報表
    └── history_page.py   ④ 歷史統計與比較
```

### 對 `hurry/main.py` 的改動（向下相容，CLI 行為不變）

1. `process_single_video()` 新增兩個選用參數
   - `frame_callback(payload)`：每幀把標註畫面與即時統計丟給介面
   - `should_stop()`：每幀檢查一次，讓介面能中止分析
   兩者預設為 `None`，不傳就跟改動前一模一樣。
2. 把原本寫死在 `main()` 裡的三段初始化抽成可重用函式：
   `load_project_config()`、`enable_cuda_optimizations()`、
   `prepare_speech_cache()`、`build_shared_components()`。
   `main()` 改成呼叫它們，介面也呼叫同樣這幾支——**單一事實來源**，
   不會出現「介面跑出來的分數跟命令列不一樣」。

## 5. 設計上的幾個取捨（口試可能會問）

**為什麼參數頁沒有 YOLO 信心值（conf）滑桿？**
各關的 conf 是實測調出來的（例如 Stage 11–12 用 0.15，其餘多為 0.70–0.75），
寫死在 `modules/models_manager.py`。做成滑桿會讓人以為可以隨手改，
反而破壞可重現性，所以只暴露「改了確實會生效、且改了合理」的參數。

**為什麼圖表是自己畫的，不用 matplotlib？**
matplotlib 預設字型沒有中文字，Windows 上會整排變成方塊；
而且嵌入 Qt 要讓 backend 與綁定版本對齊，多一層版本風險。
這裡的圖表很單純，用 QPainter 自繪反而程式碼更少、中文一定顯示正常。

**為什麼分析要放到背景執行緒？**
GPU 推論每幀數十毫秒，跑在主執行緒會讓 Qt 事件迴圈卡住、視窗顯示「沒有回應」。
所以整條管線放進 `QThread`，用 signal 把畫面與統計送回 GUI 執行緒。
畫面另外做節流（預設上限 20 fps）——**只影響顯示**，逐幀分析與輸出影片仍然是完整的。

**為什麼 ASD / TD 分組要手動標？**
影片編號沒有編碼組別資訊。從檔名猜測一旦猜錯，比較圖表會直接講出錯誤的結論，
在研究情境不能接受，所以由使用者明確指定（存在 `ui/groups.json`）。

**中止分析後資料會不會壞掉？**
不會。中止旗標放在讀幀之前，`break` 之後仍會走 `finally`：
釋放 VideoWriter、縫合音軌、寫出報告，已分析的部分完整保留。
